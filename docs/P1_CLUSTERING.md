# P1 跨平台事件聚类（v0.1）

- 状态：v0.1 已实现，见 `trend_radar/clustering.py`；测试见 `tests/test_clustering.py`。
- 目标（见 01 / 05）：同一事件在多个平台出现时，识别为一个事件，而不是几百条互不相关的信息。输出每个事件：名称、首次出现时间、涉及平台、条数、总分 / 最高分、趋势。

## 第一性原理：从这里推导

- 一个事件的身份不是单条内容的 URL，而是“同一件事”。单条内容用 URL 做身份（已有的 `items.url` 唯一键），事件用“标题语义相近 + 时间窗口内”做身份。
- 热点是变化，不是总量：聚类本身不判断爆发，只回答“这些条目是不是同一件事”。爆发判断仍靠每条内容的快照（增长 / 加速度），事件的趋势取其成员的最大增长。
- 单平台火可能是噪音，跨平台出现才是事件信号：所以事件输出里 `platform_count`（涉及平台数）是第一排序键，其次才是总分。
- 时间是事件身份的一部分：同一标题隔了很久再次出现，可能是另一件事。`time_window_hours`（默认 24）只把窗口内的内容聚在一起。

## v0.1 方法：本地 TF-IDF + 余弦相似度 + 并查集

- 分词：标题转小写、去标点；英文按词切分并去停用词；中文按字切分（不用二字：实测二字在短标题下太稀疏，同一事件的不同措辞几乎没有重合的二字，余弦只有 0.15，聚不到一起）。英文 + 一小份中文停用词表都在代码里，没有外部词典。
- 向量化：TF-IDF，`idf = log((N+1)/(df+1)) + 1`，`tf = 1 + log(count)`，向量归一化。
- 相似度：取 TF-IDF 余弦与 token 重合系数（`共享 token 数 / 较短标题的 token 数`）的大者，`>= similarity_threshold`（默认 0.35）就连边。只用余弦会把短标题的同一事件拆散（分母被大量只出现一次的词撑大）；重合系数要求至少共享 2 个 token，防止 `Apple iPhone` 与 `Apple iPad` 只因共享 `apple` 就被误并。
- 成团：并查集（union-find）把连通的条目并成一个事件；O(n^2) 两两比较，只对窗口内按分数取前 200 条做，本地量级够用。
- 事件名：取成员里分数最高的那条标题做代表名，不生成新标题（不编造）。
- 短标题保护：有效 token 少于 3 个的标题不参与合并。实测 BBC 的 `Tech Now` 是同名不同期的节目，不同 URL 标题完全相同，按标题合并会误并成一个 8 条的假事件；加保护后它拆成单条事件。短标题宁可拆散，也不要错误合并。
- 全程纯标准库，`requirements.txt` 不加新依赖，不调任何付费 LLM，不联网。

## 为什么不是 Embedding / FAISS / HDBSCAN / LLM

| 方案 | 优点 | v0.1 不用的原因 |
| --- | --- | --- |
| Embedding（sentence-transformers 等） | 语义更准，能处理同义不同词 | 要下载几百 MB 模型，首次运行慢；Windows / macOS 本地部署多一个重依赖 |
| FAISS / pgvector | 大规模相似检索快 | 本地只有几百条，O(n^2) 已够用；pgvector 还要另装数据库 |
| HDBSCAN | 密度聚类，不用预设簇数 | 依赖 scikit-learn / hdbscan，调参（min_cluster_size 等）比阈值更难校准 |
| LLM 判断事件 | 最准，能写摘要 | 付费、要联网、延迟高，违反免费优先；且 v0.1 先要证明“聚类”这条路走得通 |

这些是 v0.2 的升级路径，不是被否决的方案：当数据量上千、TF-IDF 开始把同义不同词的事件拆散时，再换 Embedding + FAISS；当需要事件摘要时，再接本地或免费 LLM。升级前必须先有真实多平台数据来对比两种方法的聚类效果。

## 配置（config.yaml 的 clustering 一节）

- `similarity_threshold: 0.35`：余弦相似度阈值。太低会把不同事件并成一个，太高会把同一事件拆散；用真实数据校准。
- `min_platforms: 1`：事件最少涉及平台数。1 表示单平台事件也保留（便于调试和看新闻类事件）；Dashboard 按平台数优先排序，跨平台事件排在前面。
- `time_window_hours: 24`：只聚最近 24 小时内的内容。

## 已知局限（v0.1，老实写下来）

- 只看标题，不看正文 / 摘要：标题措辞差异大的同一事件可能聚不到一起；标题相近的不同事件可能误并。
- 阈值 0.35 是初始假设，未用真实多平台数据校准过。
- 目前真实数据只有 RSS / GDELT（都没有互动量），Reddit / YouTube 尚未启用，所以跨平台聚类的真实效果尚未验证——测试里用的多平台数据是人工构造的标题（见 tests/test_clustering.py），只证明算法逻辑，不证明真实效果。
- 事件趋势目前只取成员的最大增长；RSS / GDELT 的增长恒为 0，趋势会显示 flat，这是数据局限，不是算法结论。
- 不做翻译、不做中文摘要（那是第二阶段）。
